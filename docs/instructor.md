# JAX·TPU 선택 심화 · 강사용 진행안

이 문서는 JAX·TPU 선택 심화 과정입니다. [기본 HF·PyTorch GPU 실습](../hf_colab_gpu/README.md)을 먼저 진행하세요. 심화 환경은 `bash scripts/setup.sh --with-jax`로 준비합니다.

## 수업의 중심 문장

“이미지를 이미 이해하고 있는 모델을 가져와 먼저 관찰하고, 우리 물체 라벨에 맞춰 학습한 뒤, 사전학습 가중치 일부까지 바꿨을 때 무엇이 달라지는지 확인합니다.”

로봇 동작을 완성하는 과정으로 소개하지 않습니다. Physical AI의 시각 인식 단계에 적용할 수 있는 모델 실험입니다. 객체 검출·좌표 추정·정책 학습과 이번 이미지 분류의 범위를 구분합니다.

## 수업 전 준비

1. `vision_ai_notbook`의 내용물을 독립 저장소 최상위에 두고 Codespaces를 준비합니다. `.devcontainer`, `.vision-lab-root`, 모델·라이선스 파일이 빠지지 않았는지 확인합니다.
2. `source .venv/bin/activate` 후 `python scripts/doctor.py`를 실행합니다. 출력된 Python·라이브러리 설치 경로를 학생에게 보여 주고 커널을 **Vision AI (Codespaces CPU)**로 선택합니다. 환경 설정은 데이터까지 준비하지 않습니다. 00번 노트북의 다운로드·전처리·저장 셀을 사전에 실행하고 `python scripts/doctor.py --data`로 확인합니다.
3. 강사 계정에서 로그인과 GPU·TPU 할당 가능 여부를 별도로 확인합니다. 단위 검사나 CPU 실행 결과는 실제 Colab 접근을 확인한 것이 아닙니다.
4. 실습 결과가 준비됐다면 `results/gpu/report.json`, `results/tpu/report.json`의 실제 장치, 데이터 지문, 체크포인트 선택 기준을 확인하고 보조 설명 자료로 보관합니다. 출력 노트북에 셀 오류가 없는지도 확인합니다. 다른 사람의 결과를 학생 본인의 실행 결과로 표기하지 않습니다.
5. 학생의 Colab CU·계정 자원과 Codespaces 사용량을 따로 안내합니다. 잔액·구독·조직 정책·자원 가용성은 계정마다 다릅니다.

## 핵심 개념을 설명하는 순서

**라이브러리와 수업 코드.** NumPy는 배열, Pillow는 이미지 처리, Safetensors는 가중치 읽기, JAX는 모델 연산·미분·컴파일, Optax는 손실·Adam, Matplotlib은 그래프를 맡습니다. 설치 이름 `Pillow`와 import 이름 `PIL`이 다르다는 예를 먼저 보여 줍니다. 모델 함수와 학습 반복문은 노트북 안에 있으며, 학생이 셀을 읽고 직접 수정할 수 있습니다. [라이브러리 안내](libraries.md)를 함께 봅니다.

**사전학습과 추론.** 고정 체크포인트의 원본 1,000개 클래스 출력부터 보여줍니다. 우리가 학습 코드를 작성하기 전에도 이미지에 대한 유용한 특징을 가지고 있음을 확인합니다. 분류 점수는 정답 여부와 다르므로 실제 이미지를 함께 봅니다.

**분류기 교체.** 새 클래스 수에 맞는 마지막 선형 계층을 만들면 그 계층은 무작위 상태입니다. 이 상태를 ‘학습 전 사전학습 모델 성능’으로 포장하지 않습니다. 고정된 사전학습 특징 위에서 새 분류기를 먼저 학습한 결과가 정량 비교 기준입니다.

**부분 파인튜닝.** 마지막 블록과 최종 정규화도 함께 업데이트합니다. 앞의 11개 블록은 고정되어 캐시를 공유합니다. 파인튜닝 이후 실제 블록 가중치 차이가 0보다 큰지, 고정 부분의 지문이 같은지 보고서로 확인합니다.

**평가.** 매 epoch의 검증 손실로 체크포인트를 선택한 뒤 테스트합니다. 같은 테스트 분할에서 두 모델을 비교해야 합니다. 가장 높은 테스트 정확도가 나온 epoch를 골라 결과로 제시하는 방식과 차이를 설명합니다.

**GPU와 TPU.** 동일한 모델을 다른 장치에서 실제로 실행하는 데 의미가 있습니다. 이번 코드는 장치 하나를 사용하며 분산 학습이나 최적화된 성능 벤치마크가 아닙니다. 컴파일·설치·파일 전송 시간을 분리하지 않은 값으로 일반적인 속도 우열을 주장하지 않습니다.

## 실행 위치를 안내하는 방법

00번·01번·04번은 Codespaces CPU에서 실행합니다. 02번·03번은 Codespaces에서 코드를 읽고 수정하되, [공식 CLI 직접 실행 안내](direct-colab-cli.md)에 따라 Colab GPU·TPU에서 실행합니다. Codespaces에서 `Run All`을 누르는 것으로 원격 장치에 연결되지 않습니다.

CLI 흐름을 하나씩 시연합니다. 터미널의 `colab --auth oauth2 sessions`로 인증을 마친 뒤, 세션 생성 → requirements 설치 → 커널 재시작 → 입력 파일 전송 → `.ipynb` 실행 → 결과 다운로드 → 종료를 진행합니다. 02번·03번 노트북의 코드 셀이 그대로 원격 실행된다는 점을 강조합니다.

설정을 바꿀 때는 노트북의 `BATCH_SIZE`, `HEAD_EPOCHS`, `FINETUNE_EPOCHS`, `HEAD_LEARNING_RATE`, `FINETUNE_LEARNING_RATE`를 직접 수정합니다. GPU·TPU 비교에는 같은 값을 사용합니다. 이전 결과는 별도 폴더에 보관하고 새 세션에서 실행하며, `OUTPUT_DIR`을 바꾸면 결과 다운로드 경로도 맞춥니다.

## 학생에게 던질 질문

- 원본 모델이 컵 사진을 ‘coffee mug’라고 출력하면 틀린 답이라고 할 수 있을까요? 새 데이터의 라벨 정의부터 살펴봅시다.
- 학습 손실은 내려가는데 검증 손실은 올라갑니다. epoch를 늘리는 것이 먼저일까요, 데이터와 설정을 살피는 것이 먼저일까요?
- 컵과 그릇이 헷갈릴 때 손잡이가 잘린 사진이 얼마나 있는지 확인해 봅시다.
- 분류기만 학습했을 때보다 파인튜닝이 나빠졌습니다. 결과를 숨기지 않고 다음 실험을 제안할 수 있을까요?
- 같은 동영상에서 뽑은 비슷한 프레임을 모든 분할에 넣으면 왜 새로운 작업대 환경의 성능을 과대평가할까요?

## 완료 기준

| 항목 | 인정할 증거 |
|---|---|
| 원본 추론 | 실제 이미지와 원본 모델 Top-5 출력 |
| GPU 실습 | 셀 오류가 없는 출력 노트북과 `status=completed`, `device.platform=gpu`인 보고서 |
| TPU 실습 | 셀 오류가 없는 출력 노트북과 `status=completed`, `device.platform=tpu`인 보고서 |
| 실제 파인튜닝 | 마지막 블록 변경, 고정 부분 불변 검증 |
| 올바른 비교 | 같은 모델·데이터·설정, 검증 기준 체크포인트 선택 |
| 해석 | 정확도·Macro F1·혼동행렬과 실패 이미지의 연결 |
| 운영 | 결과 회수와 세션 종료 확인, 내 컴퓨터에 결과 파일·출력 노트북 보관 |

일부 장치 할당이 실패하면 해당 항목은 미완료로 남깁니다. `cpu_validation`, `cpu_smoke_only` 보고서나 다른 학생의 결과로 실제 GPU·TPU 실행을 대체했다고 기록하지 않습니다. 계정 문제가 해결되면 남은 장치를 새 세션에서 같은 데이터·설정으로 실행할 수 있습니다. 학습·다운로드 실패 시에도 해당 실습에서 만든 세션 종료를 확인합니다.

## 심화·배포 자료

직접 촬영한 데이터로 확장할 때는 클래스를 추가하기 전에 각 클래스의 정의와 촬영 조건을 적게 합니다. 데이터 양, 이미지 증강, 학습률, 업데이트할 블록 수를 한꺼번에 바꾸지 말고 한 조건씩 가설을 세웁니다.

양자화는 본 수업의 필수 실습에서 제외합니다. 추가 읽을거리로만 소개한다면 가중치·연산의 수치 표현을 줄이는 개념, 모델 크기·속도·정확도의 관계, 실제 장치에서 검증해야 한다는 점을 설명합니다. 이번 실험의 float32 결과를 양자화 검증 결과로 해석하지 않습니다.

## 검증 기록 읽는 법

[현재 검증 기록](direct-test-results.md)은 직접 import와 셀 실행으로 바꾼 버전의 검사 범위와 실제 실행 결과를 설명합니다. CPU 검증과 실제 가속기 실행을 구분해서 읽습니다. 강사가 수업 전에 실제 Codespaces와 GPU·TPU를 실행했다면 날짜·장치·데이터 지문·사용한 세션 이름을 추가로 기록하세요. 측정하지 않은 성능 개선율이나 소요 시간을 보장하지 않습니다.
