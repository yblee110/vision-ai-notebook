# AI와 함께 채우는 네 개의 코드 셀

01번과 02번 노트북에 **각각 두 개씩**, 모두 네 개의 실습 코드 셀이 있습니다. 00번 준비 노트북은 그대로 실행합니다. 별도 정답 노트북 없이 각 문제의 조건을 읽고, AI에게 코드를 요청하고, 같은 노트북의 확인 셀과 실제 결과로 판단합니다.

## 먼저 준비하고, 그다음 GPU에서 확인하기

1. Codespaces에서 00번 노트북으로 모델과 데이터를 준비합니다.
2. `01_gpu_inference.ipynb`와 `02_gpu_finetuning.ipynb`를 열어 문제 조건·예상 출력·프롬프트 예시를 읽습니다.
3. AI가 만든 코드를 해당 빈 셀에 넣습니다. 설명용 문장이나 Markdown 코드 울타리는 넣지 않습니다. 함수 이름과 입력·반환 형식은 문제에서 정한 대로 유지합니다.
4. 네 셀을 채운 **입력 노트북을 저장**하고, 프로젝트 최상위 폴더의 터미널에서 아래 검사를 실행합니다.

```bash
source .venv/bin/activate
python scripts/check_student_cells.py
```

이 검사는 GPU를 사용하지 않습니다. 빈 셀, Python 문법 오류, 필요한 함수 정의의 누락을 찾습니다. 계산 결과가 맞는지까지 보장하지는 않으므로 GPU 실행 뒤 노트북 안의 확인 결과도 읽어야 합니다. 다른 위치에 저장했다면 노트북 경로를 인자로 지정할 수 있습니다.

```bash
python scripts/check_student_cells.py \
  hf_colab_gpu/notebooks/01_gpu_inference.ipynb \
  hf_colab_gpu/notebooks/02_gpu_finetuning.ipynb
```

검사를 통과한 뒤 [실행 안내](README.md)의 Google 로그인·GPU 세션 생성·라이브러리 설치·파일 전송을 진행합니다. Codespaces CPU 커널에서 01번·02번을 모두 실행해도 Colab GPU에서 실행되지는 않습니다.

```bash
colab exec -s hf-vision-gpu -f hf_colab_gpu/notebooks/01_gpu_inference.ipynb --timeout 1800
```

01번의 출력 노트북에서 **모든 코드 셀에 오류가 없는지** 확인한 뒤 02번을 실행합니다.

```bash
colab exec -s hf-vision-gpu -f hf_colab_gpu/notebooks/02_gpu_finetuning.ipynb --timeout 1800
```

`colab exec -f`는 문제 앞에서 멈춰 답을 기다리지 않습니다. AI와 코드를 고치는 시간은 실행 전에 두고, 출력 노트북에서는 확인 결과와 해석을 읽습니다. 셀 오류가 있어도 CLI가 뒤의 셀을 계속 실행할 수 있으므로 명령 종료만으로 성공을 판단하지 않습니다.

## 네 가지 문제

| 노트북 | 채울 함수 | 중요한 조건 | 실행 뒤 볼 결과 |
|---|---|---|---|
| 01 · 이미지 추론 | `infer_probabilities` | 전처리한 입력을 지정 장치로 옮기고, 추론 모드에서 클래스 확률 계산 | 확률의 개수·합·범위, 실제 이미지의 예측 |
| 01 · 예측 순위 | `topk_predictions` | `k`개를 점수 내림차순으로 정리하고 라벨 이름 연결 | Top-1·Top-3 비교, 최종 Top-5 표와 그림 |
| 02 · 한 배치 학습 | `train_one_batch` | 기존 기울기 초기화 → 예측 → 손실 → 역전파 → 갱신, 손실·정답 수·개수 반환 | 함수 확인 결과, 학습 손실과 정확도 |
| 02 · 학습 범위 | `select_finetune_parameters` | 전체를 먼저 고정하고 `head` 또는 `last_block` 범위만 학습 대상으로 선택 | 학습 대상 이름·개수, 학습 곡선·혼동행렬 |

함수의 정확한 입력과 반환 형식, 사용할 변수, 확인 코드는 각 노트북에 있습니다. AI에게 요청할 때는 함수 이름만 전달하지 말고 **문제 조건과 입력·출력 형식까지 함께** 복사합니다.

## 한 번에 하나씩 바꿔 보기

- **01번:** `k=1`과 `k=3`일 때 어떤 후보가 보이는지 비교합니다. 최종 보고서는 기존처럼 Top-5를 저장합니다. 순위가 늘어나는 것과 모델 예측 자체가 바뀌는 것은 구분합니다.
- **02번:** 학습 범위가 `head`일 때와 `last_block`일 때 대상 파라미터가 어떻게 달라지는지 확인합니다. 이번 고정 모델의 5개 클래스 설정에서는 각각 **965개**, **446,213개**입니다. 범위를 비교한 뒤 실제 두 번째 학습은 `last_block`으로 진행합니다.
- **작은 학습 실험:** 02번의 연습 모델에서는 학습률 `0.01`과 `0.1`로 두 번씩 학습해 손실을 비교합니다. 실제 DeiT 모델의 가중치와 본학습 설정은 바꾸지 않는 짧은 실험입니다.
- **결과 설명:** “AI가 맞다고 했다” 대신 어떤 확인 셀이 통과했는지, 예상과 실제 출력이 어디서 달랐는지 적습니다. 정확도가 올라가도 모든 클래스가 함께 좋아졌는지 혼동행렬에서 다시 확인합니다.

마음대로 숫자를 바꾸기 전에 그 숫자가 무엇을 뜻하는지 AI에게 설명을 요청합니다. 학습률·epoch까지 바꾸는 추가 실험은 기본 실행을 마친 뒤 별도 결과 폴더에서 진행합니다.

## 오류를 보고 다시 요청하기

프롬프트에 오류 메시지와 해당 함수, 문제 조건을 함께 넣습니다.

> 이 함수는 아래 조건을 만족해야 합니다. 실행하니 다음 확인 셀에서 실패했습니다. 원인을 먼저 설명하고, 함수 이름과 입력·반환 형식을 유지한 수정 코드를 주세요. 확인 코드를 지우거나 결과 숫자를 직접 넣는 방식은 사용하지 마세요.

01번을 고쳤다면 수정한 입력 노트북을 저장하고 사전 검사부터 다시 진행합니다. 02번을 완주한 뒤 재실행할 때는 기존 결과를 덮어쓰지 않도록 막혀 있습니다. 노트북 안내에 따라 새 결과 폴더를 정하거나 기존 결과를 보관한 뒤 다시 실행합니다. 오류 해결을 위해 결과 파일을 무조건 삭제하지 않습니다.

## 남길 기록과 종료

각 문제마다 **사용한 프롬프트 → 바꿔 본 조건 → 예상 → 실제 결과 → 해석 한 문장**을 남깁니다. 답안 코드만 제출하기보다 결과를 설명하는 데 집중합니다.

노트북에 제시한 수치·형식은 문제를 이해하기 위한 기준입니다. 기존 검증 문서의 T4 정확도 80% → 81%는 **2026-09-19에 완성된 원본 코드로 측정한 기록**이며, 이번에 학생이 작성한 코드의 실행 결과가 아닙니다. 본인의 결과와 나란히 비교하되 그대로 복사하지 않습니다.

결과 파일과 출력 노트북을 회수한 뒤 Colab 세션을 종료하고, 활성 세션이 없는지 확인합니다. Codespaces도 별도로 중지합니다. 도중에 실습을 중단했더라도 GPU 세션 종료가 필요합니다.

## 이번 변경의 확인 범위

아래는 AI 코딩 셀을 추가했을 당시의 검사 기록입니다. 이후 저장소 정리로 검사 파일 구성이 달라질 수 있으므로 당시 개수를 현재 검사 개수로 해석하지 않습니다.

노트북 형식·코드 문법·빈 셀 개수·사전 검사·미완료 상태의 결과 저장 차단을 포함한 회귀 검사 29개를 통과했습니다. 작은 PyTorch CPU 모델과 연습 입력으로 네 함수의 확인 셀, 조건 변경, 잘못된 구현 거부, 실제 학습 반복문 연결을 검사한 9개 항목도 통과했습니다.

이 검사는 학생에게 나눠 줄 빈 셀에 정답을 미리 채웠다는 뜻이 아닙니다. 학생용 파일에는 각 두 개의 빈 셀을 유지했습니다. 실제 수업 버전의 DeiT 모델을 Colab GPU에서 다시 학습하거나 저장·재로딩한 검증은 이번 변경에서 수행하지 않았습니다. 수업 전에는 작성한 함수를 넣고 GPU 실행 안내에 따라 처음부터 끝까지 실행 결과를 확인하세요.
